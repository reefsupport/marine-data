# Label matching across sources

Every source in the registry names its classes in its own way: a pixel value, a CoralNet label, a
FathomNet concept, a CPCe code. This document records the verification that all of those native labels
resolve into one reference vocabulary, `rs-benthic-v1`, so that the sources can be used together in one
training run. The verification is run on the registry alone. It reads no image data, needs no network
and finishes in seconds.

The tables below are generated by `scripts/verify_label_matching.py`; the same run writes
`results/label-matching-v1.2.0.json`. Do not edit the generated blocks by hand. After a registry
change, run `uv run python scripts/verify_label_matching.py --write`. `make labels-check` runs the
verifier with `--check` and fails when a check does not pass or when these files are out of date.

## Method

A *unit* is a source in `registry/sources` that declares a label schema or a crosswalk, a source that
appears only in the harvested vocabulary, or a crosswalk that no source claims.
For each unit the verifier compares three sets: the labels the source defines (its schema nodes, or the
native names the crosswalk uses), the edges of its crosswalk, and the nodes of `rs-benthic-v1`.

| # | Check | Outcome |
|---|-------|---------|
| 1 | Coverage. Every native label has exactly one crosswalk edge, or is an unmappable edge that carries a note. No label is missing, duplicated or extra. | Hard |
| 2 | Resolution. Every edge target is a node of `rs-benthic-v1` on the axis the edge declares (taxon, growth form or condition). A bare id that exists in more than one namespace is reported as ambiguous. | Hard |
| 3 | Fidelity. An edge is `exact`, `coarsened`, `approximate`, `narrower` or `unmappable`. A lossy edge carries a note, and an `exact` taxon edge reaches a node of the label's own rank or a leaf. | Hard; see below |
| 4 | Cross-source agreement. For each `rs-benthic-v1` node, which (source, native label) pairs feed it. An exact edge whose native name shares no word with the node is listed; bare codes and numeric ids are counted but not compared. | Review list |
| 5 | Legacy consistency. Each Coralscapes-95 class names its Coralscapes-39 class. The two targets must be equal, or the 95-class target must refine the 39-class target. Conditions must be equal. | Review list |
| 6 | Condition axis. Which sources carry the condition axis, and whether a label with a health word (bleached, pale, diseased, dead) reaches the matching condition node. | Review list |
| 7 | Ignore semantics. The ignore index is 255. Every pixel value that is not a declared class, and every unmappable label, maps to 255 in every training scheme. | Hard |

Checks 4 to 6 produce lists for a reviewer. They are counted in the generated review table and they
never fail the build. Checks 1 to 3 and 7 fail it.

Two kinds of finding that predate this verifier are pinned rather than failed, so that they can
only decrease: lossy edges in the older crosswalks that carry no note, and schema nodes that no edge
of any crosswalk of that schema covers. Both are counted in the review table. A new instance of either
fails the check.

## Coralscapes V1 to V2

Coralscapes V2 has 95 classes. Each row of its class table names the 39-class Coralscapes V1 class it
came from. The V2 crosswalk copies that name into the edge note as `[legacy: <name>]`. Check 5 pairs
each V2 edge with the V1 edge of that name. A V2 class may refine its V1 class, for example a coral
genus under a V1 morphology class; it may not move to an unrelated node, and its condition must not
change. The classes whose target differs from the V1 target are listed below.
The [v1.2.0 changelog](../CHANGELOG.md) and the "Coralscapes V2" section of the Hugging Face card
state the same facts for readers of the release.

## Training jointly

To train on several sources at once, express every label in `rs-benthic-v1` ids and nothing else. Map
each source through its crosswalk to the node ids of `rs-benthic-v1`; a source never contributes its
own class numbers to the loss. Where an edge is `coarsened`, the source cannot say more than the
target node says, so supervise that pixel or point at the target node and, where the head is finer,
at the ancestors of the node through the taxon tree: a label of "Acropora" must not push a pixel
towards one species of Acropora, and a label of "Hard coral" must not push it away from any genus.
Coarsen a finer source the same way when a coarser source is trained alongside it. Condition and
growth form are separate heads that read the condition and form targets of the same edge, and a source
with no edge on an axis contributes nothing to that axis. Index 255 means *ignore*: it carries no
gradient and is not counted in any metric. The same 255 is produced for pixels outside the source's
declared classes and for every unmappable label above, so a source cannot introduce an undeclared
class by accident.

One pair of twin labels trains differently in the two coarse views. In `coral-binary` the V1 label
"other coral alive" (`CORAL`) and the V2 label "cirrhipathes" (`CORAL`, node `CN_ANTIPATHARIA`, black
coral) agree, because the binary view counts black corals as coral like `SC` (D11). In `benthic-coarse`
they do not: the V1 label is `HC`, while the V2 label maps to no class there (`255`, ignored), since
`CN_ANTIPATHARIA` is not part of any `benthic-coarse` class. The node is deliberately not forced into
`HC`. A head that needs the twins to agree should train on `coral-binary` or express both sources in
`rs-benthic-v1` ids.

`label_schemes.py` and `labels.py` implement these rules. `docs/LABELS.md` describes the training
schemes built on top of them.
